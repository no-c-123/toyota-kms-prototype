# System architecture

## Overview

The system has two halves that share one knowledge base:

1. **Offline pipeline (Python, `ml/`)** turns the raw documents and the ontology into models and indexes.
2. **Online system (`web/`)**: stateless serverless functions on Vercel answer requests with those artifacts,
   and a React frontend presents them.

There is no database. The knowledge base (`web/lib/data/kb.js`, ~700 KB) is generated by the pipeline and
bundled with the serverless functions, so every request is answered in a few milliseconds and the system has
no external dependencies (the optional LLM is the only exception, and it is off by default).

## Data (`data/`)

| File | Content |
| --- | --- |
| `documents.json` | 72 documents, 12 per category (Manufacturing, Quality, Safety, R&D, Supply Chain, HR & Training). Each has id, category, type, department and the title and text in English and Spanish. |
| `concepts.json` | Ontology: 6 principles (TPS, Just-in-time, Jidoka, Toyota Way, Kaizen, Respect for people) and 38 concepts (andon, kanban, poka-yoke, 5S, SMED…), each with bilingual definitions, keywords and the principle it supports. |
| `eval/chatbot_dev.json` | 45 questions + 6 conversations used to tune the chatbot. |
| `eval/chatbot_test.json` | 45 questions + 4 conversations written and committed before tuning; never used to adjust the system. |

## Text processing (shared by Python and JavaScript)

`ml/text_processing.py` and `web/lib/engine/text.js` implement the same rules:

1. lowercase and strip accents (`Inspección` → `inspeccion`);
2. keep letters and digits;
3. remove English and Spanish stop words;
4. prefix stemming to 5 characters (`suppliers`, `supplier` → `suppl`; `inspección`, `inspectores` → `inspe`),
   chosen on the dev set: it raised precision@1 from 0.79 (no stemming) to 0.92;
5. unigrams + bigrams.

TF-IDF follows scikit-learn's formulas (`tf = 1 + ln(count)`, `idf = ln((1+n)/(1+df)) + 1`, L2 norm).
`ml/check_parity.py` runs 26 texts through both implementations: features are identical and weights differ by
less than 1e-7.

## Components

### 1. Automated classification
* `ml/classifier.py` trains and compares Naive Bayes, Linear SVM and Logistic Regression with 4-fold grouped
  cross-validation × 5 repeats (both language versions of a document always stay in the same fold).
* Logistic Regression (C=30) is exported (vocabulary, idf, coefficients) and executed by
  `web/lib/engine/classify.js`, which also returns the words that weighed most in the decision.

### 2. Recommendation system
* **Content-based** (`ml/recommender.py`, precomputed): `score = 0.8 · cosine + 0.2 · Jaccard(shared concepts)`.
  The ontology term relates documents that describe the same TPS concept with different words.
* **History / context-based** (`web/lib/engine/recommend.js`, per request): the browser keeps the session's
  searches and opened documents; the API builds a profile vector with exponential decay (0.7 per step),
  ranks unseen documents by cosine similarity plus shared concepts, and explains each suggestion
  ("because you searched …").

### 3. Chatbot (`web/lib/engine/chatbot.js`)
1. Language detection (Spanish / English).
2. Rules: greeting, help, thanks, **category lists** ("¿Qué documentos hay de seguridad?") and **concept
   definitions** from the ontology ("What is kanban?").
3. Retrieval: query expansion with a small thesaurus (`carro` → `vehículo`), TF-IDF cosine against the 72
   documents, plus a boost when the document describes a concept found in the question (scaled by concept rarity).
4. Conversation context: short or anaphoric follow-ups ("¿y cada cuánto se practica?") are combined with the
   previous question.
5. Confidence check: the answer is given only with enough evidence (score ≥ 0.08 and two of the user's words in
   the document, half of them, or a shared concept). Otherwise the bot says it has no information.
6. Answer: the most relevant sentences of the best document, its id as the source, the top-3 sources and related
   documents. If `ANTHROPIC_API_KEY` is set, `llm.js` rewrites the answer from the same documents (RAG); any
   error falls back to the extractive answer.

### 4. Knowledge graph (`ml/knowledge_graph.py`)
NetworkX graph with 6 node types and 7 relation types:

| Relation | From → to | Count |
| --- | --- | --- |
| classified_as | document → category | 72 |
| describes | document → concept / principle (found in the text) | 137 |
| supports | concept → principle | 20 |
| pillar_of | principle → principle | 4 |
| is_a | document → document type | 72 |
| owned_by | document → department | 72 |
| related_to | document → document (recommender score ≥ 0.15) | 39 |

Exports: `web/src/data/graph.json` (interactive view with filters, search and neighbor highlighting),
`ml/output/knowledge_graph.html` (PyVis) and `ml/output/knowledge_graph.png`.

## API

| Endpoint | Input | Output |
| --- | --- | --- |
| `POST /api/chat` | `{ message, history? }` | intent, answer, primaryDocId, sources, related, suggestions, usedContext, confidence |
| `GET /api/search?q=` | query | ranked documents with score, concept boost and snippet |
| `POST /api/recommend` | `{ docId? , queries?, viewed? }` | `related` (content) and/or `forYou` (history) |
| `POST /api/classify` | `{ text }` | category probabilities and evidence words |
| `GET /api/health` | — | status, size of the knowledge base, answer mode |

Inputs are length-limited and validated; the API keeps no state between requests.

## Frontend (`web/src/`)
React 18 + Vite, hash routing, six sections: Asistente (chat + "Recomendado para ti"), Explorar (search,
filters, document viewer with related documents and concepts), Clasificar, Grafo, Métricas (evaluation
dashboard + SUS questionnaire) and Cómo funciona (architecture).
